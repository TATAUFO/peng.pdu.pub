### PDU协议——点对点的社交网络服务

* email: liupeng@pdu.pub

**摘要：**

信息传播系统应当允许参与者自由地发布信息，同时有效地获取信息。本文提出一种无需依赖特定第三方身份认证或内容裁决服务的点对点社交网络系统。系统以同一私钥签名、通过引用形成全序的消息集合定义发布者身份，并将信息发布与信息获取分为两个独立角色：发布者通过签名消息表达和交互；获取者无需身份，依据发布者之间的主动交互和自己的本地规则，构建可见身份集合。交互体现的是将对方作为同类主体对待的认知，而非对其观点、品行或内容的认可。系统中所有消息均为公开信息，屏蔽和过滤均为获取者的本地操作。系统不统一判定信息价值，不执行封禁或惩罚，也不要求全网拥有相同的信息或可见身份范围。所谓奖惩，是获取者区别对待发布者所形成的传播效果。对于破坏身份全序结构的分叉，接收方保留此前已经接受的历史，并停止接受该身份的后续消息；交易等上层应用所需的一致性与不可毁约保证，由相应应用另行建立。

## 简介

信息传播包含两个相互关联的目标：发布者能够按照自身意愿表达，获取者能够从众多来源中取得对自己有意义的信息。中心化社交平台通过账户管理、关系维护、内容筛选和推荐，为这两个目标提供了便利。但当身份、关系和传播渠道都依赖同一个服务时，使用者也将信息传播的决定权交给了服务提供者。离开服务可能意味着失去原有的关系和受众，即使内容本身仍可保留，也难以延续既有的社交身份。

将服务分散到多个管理者手中，可以改变这种依赖的分布，但身份如何成立、谁能够被看见、哪些信息值得获取，仍然需要分别回答。PDU 将这些问题拆开：通过公开的签名消息建立身份，通过发布者之间的交互提供身份间的关联，再由每个信息获取者决定自己的可见范围和过滤方式。

在这种系统中，没有必要统一判断什么是垃圾信息。同一内容可能对某个获取者有意义，对另一个获取者毫无意义；一个人短时间内创建多个身份并大量发布内容，也不因此必然构成恶意。系统提供可识别的来源和可选择的获取范围，内容价值由获取者自己判断。

PDU 的目标是使信息在愿意接受它的范围内传播。自由发布不意味着有权要求其他人接收、保存或转发；获取者拒绝某个来源，也不意味着能够撤销对方的发布能力。双方通过各自的选择，共同形成实际的信息传播范围。

这一设计与[《视界受限实在论》](/hcr/chapter_0/)中的个体和视界概念相呼应：有序事件集合构成身份，主体通过交互认知其他主体，获取者根据自身取得的信息形成局部世界。这些概念提供了设计动机；以下各节进一步说明其在信息传播系统中的具体含义与边界。

## 目标与边界

系统的基础目标是允许发布者独立创建和使用身份，并让获取者自主选择信息来源。身份的成立不需要现实身份认证，获取信息不需要创建身份。第三方可以提供存储、检索和连接等服务，但任何特定第三方都不应成为身份验证或本地筛选不可替代的裁决者。

理解这一目标，需要区分三个层面：

| 层面 | 含义 |
| --- | --- |
| 身份成立 | 同源消息满足全序结构，能够被作为一个持续的发布主体来识别。 |
| 身份可见 | 某个获取者依据已知交互和本地规则，将该身份纳入自己的信息来源范围。 |
| 内容评价 | 获取者或上层应用判断具体内容是否有意义、是否展示，以及如何处理。 |

满足身份结构不意味着被任何获取者接纳；进入可见范围也不意味着内容受到赞同。系统不验证一把公钥背后是否对应唯一自然人，不限制一个使用者拥有多少身份，也不为所有获取者建立统一的内容价值标准。

本文所说的不需要统一共识，是指不要求全网统一消息历史、可见身份集合或内容评价。消息格式、签名验证和全序结构仍然需要清楚的共同定义，才能让参与者理解和核验同一份信息。

PDU 面向公开信息传播。私密通信、交易确认以及法律和合规判断，属于其他协议、应用或规则的职责。基于 PDU 构建这些功能时，应明确各自增加的条件，不能将身份可追溯直接等同于交易不可毁约或内容已获认可。

## 使用者的两个角色

**信息发布者**是系统中的可见角色。发布内容、回复、引用、转发和点赞等行为，以签名消息的形式对外表达，并通过引用构成有序的行为历史。这个同源全序消息集合就是发布者身份。公钥使消息来源可以被识别，消息历史使他人能够持续地对待同一个来源。

发布者所追求的影响力可以有不同尺度。影响力并非只由受众数量衡量，也涉及持续时间、受众是谁以及产生何种影响。一个学者可能更看重十个同行三十年的回应，而不是一百万人三天的浏览。不同发布者可以按照自己的目的理解传播的价值。

**信息获取者**是执行信息选择的角色。获取者不需要身份，可以只接收和阅读信息，也可以在本地选取起始身份、调整可见范围、屏蔽来源或过滤内容。这些操作不构成发布消息，不要求签名或公开，也不会因为使用者同时拥有发布者身份而自动成为该身份的行为。

两个角色不存在一对一绑定。一个使用者可以拥有多个发布者身份，共享或分别使用不同的获取规则；也可以没有任何发布者身份，仅作为获取者使用网络。只有当使用者主动发布一条表达或交互消息时，这个行为才进入相应发布者的公开历史。

发布者需要先取得相关信息才能与之交互，但信息的取得可以来自日常可见范围，也可以来自手动发现、直接交换或检索。日常过滤范围不是发布权限边界。获取者临时查看一个新来源，并不意味着必须持续接收它的全部消息。

## 消息

消息是系统中公开发布和交互的基本数据单位。发布者身份及身份间的交互关系，都由获取者依据消息在本地构建。获取者无需另行接受某个第三方对身份历史的解释。

每条消息由消息内容、引用列表和签名组成。内容可以包含文字、图片等信息，以及发布、回复、引用、转发或点赞等交互方式。引用列表记录其他消息的签名，用以建立消息之间的先后关系；涉及回复或引用时，也应包含相关消息的引用。发布者对内容和引用列表的哈希值进行签名，接收方据此验证来源及数据完整性。

发布者可以在引用列表中加入其他身份较新的消息，将自己的消息与更多已知事件建立先后联系。这种联系表明消息之间的顺序，不直接给出真实世界中的时间间隔。

屏蔽不属于消息类型。它不表达发布者之间的一条公开关系，而是获取者如何处理已取得或准备取得的信息的本地规则。

对信息的判断可以涉及单条内容，也可以涉及来源的持续行为。例如，一条餐馆推荐可能对某个获取者有用，而同一来源反复发布类似推荐，可能使该获取者不再愿意接收。另一个获取者也可能正需要这样的持续信息。身份历史为这些判断提供上下文，但系统不替任何获取者作出价值结论。

## 发布者身份

### 同源全序

发布者身份由同一私钥签名、具有全序关系的消息集合定义。全序意味着任意两条属于该身份的消息，都具有确定的先后关系。维护这个顺序是发布者的责任。

为形成这样的结构，每条消息引用列表中的第一项，应指向同一私钥签发的上一条消息。对于该私钥签发的第一条消息，第一项为 0，表示起点。其余引用可以建立与其他消息的关系。同一身份内部形成全序，跨身份引用则形成更广泛的偏序关系；系统不要求所有身份的消息具有统一的全序。

顺序使获取者能够理解一个身份的持续变化。发布者先表达一种观点、之后作出修正，这两条消息可以同时保留，并按顺序构成其历史。内容上的矛盾不等于身份结构的破坏，也不要求所有获取者对这种变化作出相同评价。

只要消息满足这一身份定义，其背后是个人、组织还是人工智能，都具有同等的系统地位。系统识别的是签名来源及其有序历史，不以背后实体的类别决定其资格。

### 顺序、时间与历史可得性

消息链能够提供可验证的顺序，但链条长度不等于身份年龄。短时间内可以产生大量有序消息，多个身份也可以并行积累历史。引用一条较早的消息，只能建立与该消息的先后关系，不能单独证明当前身份已经持续存在很长时间。

获取者可以根据自己的长期观察、其他身份对既有消息的引用，以及所见内容判断一个身份。这些都是本地判断的依据，不构成统一、不可伪造的身份创建成本。历史较长、消息较多的身份提供了更多可供观察的材料，但不因此必然更有价值，也不必然比新身份更值得接收。

签名使接收方能够验证已取得消息的完整性，引用使消息之间的断裂或冲突在相关证据可得时能够被发现。但这些结构并不保证每条消息都一直可获取，也不能证明发布者没有隐藏尚未被接收方获知的尾部或分支。

发布者应保存自己完整的消息链，并通过自有节点或自行选择的其他节点提供查验。获取者不必保存全网历史。遇到尚未取得的前驱消息时，可以将相关消息暂列为待验证状态，并在自己的资源范围内补取；缺少信息本身不是分叉证据。

### 分叉与已接受历史

当同一发布者对同一前驱签发两条不同的后继消息时，形成分叉。对于同一公钥的多个不同起点，同样无法将其作为一条唯一的消息链来接受。分叉使获取者不能仅依照发布者提供的链式关系，将这些消息排列为一个完整的全序身份。

分叉与内容评价具有不同性质：只要相关签名和消息均可验证，分叉就有客观的结构证据；发现证据不依赖获取者是否喜欢该发布者。引用列表第一项指向其他发布者的消息，也不满足同源链的要求。发布者需要自行维护身份结构，无论其破坏出于何种动机或技术原因。

发布者可能先让一条分支被接受，之后再公开从更早位置分出的另一条分支，试图否定先前的信息。如果发现分叉就撤销此前接受的全部历史，发布者反而能够利用这一行为破坏已建立的信息依据。因此，接收方采用以下处理原则：

1. 保留此前已经验证并接受的消息，以本地先接受的历史为准，不因后来发现分叉而自动撤销。
2. 保存可验证的分叉证据，后来取得的冲突消息不用于替换已经接受的历史。
3. 从发现分叉起，停止将该身份的后续消息作为正常的全序身份历史接受。为核验冲突而取得或保存消息，不等于继续接受它。

这一处理是获取者对破坏身份定义的来源所作的区别对待。发布者仍然可以签名并发送任何消息，系统不会撤销其发布能力。分叉所失去的是获取者将这些消息继续作为同一个全序主体对待的基础，而非生成和发送数据的能力。

不同接收方可能先接受不同分支，也可能在不同时间发现冲突。PDU 不统一这些本地历史。保留已接受的消息，表示保留信息记录，并不保证消息陈述为真，也不自动确定其中承诺或交易的效力。

如果某项交易建立在这些信息之上，交易应用需要用更高层的机制确定确认条件、冲突处理和不可毁约规则。发布者不能仅通过制造分叉要求 PDU 接收方删除既有记录，但 PDU 本身不提供交易终局性。

## 可见身份集合

一个使用者可以自由生成新的密钥和身份，但新身份不会因此自动进入其他获取者的日常信息范围。可见身份集合就是某个获取者按照自己的规则选取的发布者范围，它构成持续获取信息的来源基础。

这个集合不同于传统社交平台中的关注列表。它更接近获取者自行划定的平台用户范围：在这个范围内，获取者还可以进一步选择主题、内容和展示方式；在范围之外，也可以通过临时探索发现新的身份。可见身份集合不决定其他人能否发布，不构成全网账户名单。

### 同类认知

发布者之间的主动交互体现了一种同类认知：把对方作为与自己一样，可以表达、回应并持续参与交互的主体来对待。喜欢、崇拜、反对、批评或鄙视，都可以是这种对待方式的具体表现。

这里的“同类”不是生物学上的物种分类，也不要求相同观点或共同利益。它指作为交互主体的共同地位，因此可以包含个人、组织和人工智能。对方被作为主体对待，不等于其言论受到认可，也不表示其内容满足某种道德、法律或合规标准。

获取者可以依据这些公开交互，把对某些身份的认知扩展到更多身份。本文将这一过程称为**认知传递**。这种传递提供的是可见范围扩展的依据，不是信誉或观点正确性的担保。

### 认知传递机制

获取者首先选定若干起始身份，作为第零层。这些身份可以是自己的发布者身份、直接认识的发布者，也可以是通过内容、朋友介绍或检索服务发现的身份。选择起始身份属于本地操作，不要求发布任何消息。

从起始身份出发，获取者依据本地规则，找到它们主动评论、转发、引用或点赞等交互所指向的对象身份，形成第一层引入身份。若需要继续扩展，再依据第一层身份的主动交互寻找第二层，以此类推。计算时可以对重复身份去重，并受本地设定的层数和规模限制。

交互方向是这一过程的关键。如果 A 是已选定的起始身份，A 主动评论 B，则获取者可以通过 A 将 B 引入。评论表达赞同还是反对，不改变其作为主动交互的性质。如果只是 B 单方面评论 A，则不能据此认为 A 已经把 B 作为交互对象，也不能沿 A 的这条关系引入 B。一个方向上的交互不要求另一个方向已经回应。

身份被引入后，获取者仍可以反对其观点、过滤其部分内容，或随时将其移除。同样，获取者也可以保留某个身份的信息，而不继续沿该身份的交互关系扩展。是否阅读某个来源，与是否以它作为继续发现其他来源的依据，可以分别决定。

作为一种简单的初始规则，获取者可以先只展开一层，并将不同时期的交互同等作为引入依据。较早的交互仍然是一条存在过的关系，但不要求获取者永久保留由此引入的身份。层数、采用哪些交互以及是否使用时间范围，均由获取者自行选择，不由系统统一指定。

### 本地屏蔽与路径选择

屏蔽是获取者本地规则的一部分。系统不将屏蔽定义为公开行为，也不设立对所有获取者生效的公共黑名单。即使某个获取者同时拥有身份 A，其屏蔽 C 的操作也不会成为“A 屏蔽 C”的公开关系。

本地规则可以分别作用于身份和引入路径。例如，获取者决定不再通过 A 扩展身份范围，则仅由 A 引入的身份可以从范围中移除；如果 C 还能够通过其他保留的路径被引入，C 仍可留在集合内。若获取者明确排除的是 C 本身，则其他引入路径不能自动覆盖这一排除。

这些选择只影响当前获取者，不要求其他获取者同步采取行动。获取者也可以调整或撤销自己的规则，而无需向任何身份请求许可或公开理由。

### 规模与资源边界

认知传递可以渐进展开，但渐进过程本身不保证集合规模受控。即使只展开一层，某个起始身份也可能与大量身份交互；即使身份总数较少，也可能产生大量内容。因此，来源选择和资源分配需要分别处理。

获取者可以设置可见身份总量、每条引入路径的新增配额、单位时间的扩展预算，以及单个来源的消息处理、带宽和存储额度。对于缺失引用，还可以限制追索深度、请求次数和待验证缓存大小。达到预算后，可以暂停扩展、延后获取或重新调整选择。

这些限制表达的是当前获取者愿意为信息投入多少资源，不是对发布者行为的公共判决。某个来源因本地预算而暂时不被处理，不代表它无价值，也不影响其他获取者为它分配更多资源。

不同获取者掌握的消息和采用的规则可能不同，因此其可见集合也不同。即使规则相同，在消息到达时间、历史可得性或本地预算不同的情况下，实际结果也可能不同。这种局部性是系统的正常状态。

## 新身份的发现与系统启动

新身份的成立不依赖他人许可，但它不会自动获得受众。对新身份而言，被发现和被持续纳入获取范围是两个不同过程。

新身份可以通过直接交换消息、公钥及消息获取地址、线下介绍或公开链接被发现。获取者可以在独立于日常信息流的探索过程中，按需取得有限的消息和身份历史，再决定是否将其加入可见集合。如果随后以自己的发布者身份与之交互，这条交互又可以成为其他获取者扩展范围的依据。

这一过程不必等待新身份先进入某个公共名单，也不必依靠特定检索平台。例如，两名使用者可以直接连接自己的节点，由一方向另一方提供签名消息及可验证的历史。接收方查看后可以仅在本地纳入该身份，也可以另行发布评论；前者改变自己的范围，后者才形成公开交互。

第三方检索或推荐服务可以扩大被发现的机会，但推荐结果不自动成为获取者的选择。获取者可以采用多个入口，也可以手动补充身份。身份被发现后能否持续获得受众，取决于具体获取者对其内容和行为的判断，不能仅凭账户年龄或消息数量决定。

系统启动初期可以由已有关系的使用者交换身份，也可以引入具有不同表达方式和兴趣的 AI 发布者。只要维护同源全序，AI 身份与其他身份具有同等地位。AI 可以提供初始内容和交互，但其存在不要求获取者将其设为起始身份，也不意味着多个 AI 身份就对应多个独立的控制者。

## 节点与网络传播

### 节点的职责

节点是保存、获取和传递消息的设备或服务。一个节点可以服务多个发布者和获取者，一个发布者也可以通过多个节点提供自己的历史。节点与发布者身份没有强制绑定关系，不发布内容的获取者同样可以运行节点。

用户节点可以保存自己的发布历史、本地获取规则和已取得消息。服务节点可以保存更广泛或更持久的公开数据，提供检索、备份和转递。两者都不必拥有全网消息，也没有义务接收和保存每个来源。

接收到数据、验证消息、接受身份历史、展示内容以及保存或转发，是不同的处理步骤。某条消息可以为核验引用而被临时取得，却不进入日常信息流；某个节点也可以选择转递公开数据，而不把相关身份作为自己的阅读来源。

### 发现、补取与转递

在网络连接层面，参与者需要知道至少一个可连接节点。节点地址可以直接交换，也可以从使用者选择的多个发现入口取得。连接的建立应允许直接通信或经可替换节点转递，具体传输实现可以不同，但不应让一个特定入口成为身份成立的必要条件。

发布者将消息交给相连节点，节点根据自己的资源和选择保存或转递。获取者也可以按需向发布者节点、已知副本节点或检索服务请求消息。对于缺失的前驱或交互目标，可以沿已有引用进行补取；暂时无法取得时，保留待验证状态或按本地预算停止追索。

当发布者离线时，其他节点上保存的副本可以继续提供消息。如果没有任何可达节点持有所需内容，则无法保证立即取得。来源可验证与数据可得是两个不同条件，发布者可以通过自有副本或自行选择的备份服务改善后者。

某个中间节点拒绝转递时，获取者可以尝试直接请求或选择其他持有副本的节点。但只有在存在可达来源时，这种替换才能完成。PDU 不承诺每条消息一定到达所有潜在受众，也不把这种传播限制视为发布者失去发布资格。

### 公开交互与网络转发

节点转递一条已有消息，并不自动构成某个发布者的公开交互。只有发布者签发新的评论、引用、转发或点赞消息时，才形成可供认知传递使用的关系。

当一个已可见身份引用未知身份的内容时，获取者可以先接受已可见身份的交互消息，再根据需要补取被引用内容和相关历史。取得目标内容不意味着必须继续展开其全部关系，也不要求把所有被引用来源一次性加入日常范围。

通过这种方式，内容可以经由公开交互被更多人发现，而获取者仍保有决定持续获取范围和投入资源的权利。

## 激励与传播效果

PDU 不对任何发布者实施奖励或惩罚。即使发布者制造分叉、发布重复内容，或发布某个获取者认为毫无意义的信息，仍然能够签名和发送消息。系统没有撤销其发布能力的公共执行者。

所谓奖励与惩罚，是信息获取者区别对待发布者所产生的效果。愿意取得、阅读和继续传播某个来源的信息，可以扩大其影响范围；减少获取、停止沿其关系扩展或将其屏蔽，则会缩小它在相应获取者及传播路径上的影响。

最大的惩罚是没有任何受众愿意接受该发布者的信息。此时发布行为仍可继续，但不再抵达任何受众。这是一种可能的传播结果，不是协议能够宣布或保证执行的全网封禁。

对于重视某个身份持续影响力的发布者，受众的回应可以影响其后续行为。它可能调整表达、内容或交互对象，以维持自己重视的受众关系。如果发布者不在意这些反馈，获取者仍然可以通过本地规则停止为它分配注意力和资源，无需先使其改变意愿。

同一行为可能使发布者失去一部分受众，同时获得另一部分受众。赞同和反对都可能带来交互，交互也可能带来新的可见性。因此，传播范围扩大并不证明内容更正确、更善良或更有价值；传播范围缩小也不构成相反的证明。

本文中的“有意义的信息”或“垃圾信息”，均相对于具体获取者的目标而言。大量发布、多个身份或自动生成内容，本身都不构成系统判定恶意的依据。内容的法律、合规及其他评价，可以由建立在 PDU 之上的应用和规则处理，不能从身份成立或可见性直接推导。

系统层面的效果，是各获取者独立选择之后形成的传播分布。它不要求统一的好坏标准，也不保证所有人的偏好最终收敛。其目标在于让获取者能够持续调整自己的信息环境，让发布者在愿意接受其信息的范围内建立影响。

## 公开性与隐私边界

PDU 中所有消息都是公开的，任何获取者原则上都可以取得和验证它们。系统不设置基于身份的阅读权限，也不存在“仅某些身份可见”的私密消息类型。从这个意义上说，PDU 的消息模型中没有隐私这一属性。

理论上的公开不等于每个节点实际持有全网内容。由于网络传输、实时性、资源和获取必要性不同，每个获取者通常只取得自己选定来源的一小部分信息。这种差异来自实际获取条件和本地选择，不是某些获取者被授予了阅读权，而其他人没有。

发布者身份由签名来源及其全序历史定义，不需要提交手机号、邮箱或其他现实身份信息。系统不负责建立或验证公钥与现实身份的对应关系，但这也不是关于现实匿名性的保证：使用者自行公开的内容，仍可能在系统之外被用来建立关联。

公开意味着内容可以被他人保存和继续传播。发布者停止提供某条消息，并不意味着其他节点也会删除其副本。不希望公开的信息，应通过其他适合的通信方式传递。私密通信可以使用另行建立的联系渠道，但不属于本文的公开消息系统。

获取规则则是本地操作状态，不是系统中发布的内容。系统不要求获取者公开自己的屏蔽列表、阅读记录或选择规则；与此同时，本地执行这些操作也不等于对网络访问行为完全不可观察作出保证。

## 第三方服务

第三方可以基于公开消息提供便利。其作用是扩大可得信息、改善连接或降低本地处理负担，而不是决定某个身份是否有权存在。服务提供者也可以依据自己的规则选择保存和转递哪些内容，获取者则可以选择其他服务或使用自己的节点。

| 服务 | 作用与边界 |
| --- | --- |
| 存储与备份 | 保存发布者历史及内容副本，提高离线时的可得性；保存副本不赋予修改签名历史的能力。 |
| 检索与发现 | 帮助获取者找到消息和新身份；搜索结果不自动成为本地可见集合。 |
| 连接与转递 | 在节点无法直接通信时辅助传递消息；服务入口可以替换，消息仍由接收方验证。 |
| 关系计算 | 根据获取者选择的规则辅助计算可见范围；采用此服务是获取者自己的选择，可以改用本地计算。 |
| 传播统计与商业服务 | 根据已取得的公开交互进行统计或连接发布者与需求方；统计不代表全网完整情况，也不能仅凭公钥数量推断实际人数。 |

公开数据使其他服务有机会提供相同或相近的功能，但并不保证所有服务已持有相同副本。减少对特定服务的依赖，需要可替换的消息来源、使用者对自身历史的保存，以及可独立验证的消息结构共同支持。

## 获取规则的评估

系统不统一评判内容价值，但不同的本地获取规则仍然可以根据使用者自己的目标进行比较。评估对象是这些规则能否帮助获取者取得所需信息，以及需要投入多少资源。

可比较的场景包括：起始身份关联大量新来源、某个来源持续高频发布、多个身份共同参与交互、新身份尚无既有关系、历史暂时缺失，以及分叉证据延后到达。这些场景用于观察规则的行为，不预先把身份数量、频率或内容形式定义为恶意。

| 评估方向 | 可以观察的结果 |
| --- | --- |
| 信息获取效果 | 获取者自己认定有意义的信息所占比例，以及希望取得却未能取得的信息。 |
| 新身份发现 | 从直接交换、探索或公开交互到被持续纳入范围的机会和所需过程。 |
| 范围可控性 | 不同层数、路径配额和本地排除规则下，集合的规模及变化。 |
| 资源投入 | 消息验证、历史补取、关系计算所需的时间、带宽和存储。 |
| 历史处理 | 乱序、缺失和分叉证据出现时，是否保留已接受记录，并正确区分待验证信息与冲突证据。 |

可以在相同的消息和交互样本上比较不同本地规则，再由具有不同需求的获取者分别评价。使用 AI 或其他模拟身份时，需要说明其控制关系和生成方式，避免把模拟身份数量当作独立参与者数量。

这些指标不形成全网统一的内容评分，也不要求公布实际使用者的本地规则。它们用于检验实现和选择策略。本文提出的是系统机制及评估方向，不将尚未进行的测量作为已经实现的效果。

## 结论

PDU 以同源全序消息定义发布者身份，以公开交互形成身份之间的关联，再由无需身份的信息获取者按照本地规则构建可见范围。发布者与获取者相互独立，身份成立、身份可见和内容评价也分别属于不同层面。

主动交互体现的是对同类主体的认知，而非观点或品行上的认可。获取者可以据此进行认知传递，并通过本地屏蔽、路径选择和资源限制调整自己的信息环境。新身份可以经由直接交换和探索被发现，不必先取得公共资格或特定服务的许可。

系统中的消息均为公开信息，而实际持有的消息和可见身份集合可以因获取者而异。系统不要求统一的信息历史或价值判断，不执行对发布者的封禁与惩罚。发布能力始终与受众是否愿意接受相区分，所谓奖惩表现为获取者区别对待之后产生的影响范围变化。

分叉破坏了全序身份的基础。接收方保留此前已经接受的历史，在发现分叉后停止接受该身份的后续消息，而不因发布者后来制造冲突撤销已有记录。需要交易一致性或不可毁约保证的应用，应另行建立相应机制。

通过这些边界，PDU 将公开表达、身份延续和信息选择连接起来，使参与者可以独立发布，也可以独立决定自己愿意看见什么。
